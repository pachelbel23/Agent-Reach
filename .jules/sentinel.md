## 2026-07-28 - [Harden configuration permissions and sensitive data masking]
**Vulnerability:** Configuration files/directories had overly permissive access (0o644 instead of 0o600, or lacked directory-level protection), and session identifiers/cookies (ct0, sessdata, csrf, cookie, jct) were leaked in configuration dictionaries because `Config.to_dict()` only masked keys containing 'key', 'token', 'password', or 'proxy'. In addition, duplicate credential-syncing logic resulted in credential files momentarily created with insecure permissions before explicit chmod.
**Learning:** `os.open` with `O_CREAT` does not alter permissions of existing files on overwrite, so an explicit `os.chmod` is necessary to guarantee restrictive permissions when overwriting existing files. Also, generic security masking keywords fail to capture varied platform-specific naming conventions for sensitive credentials, requiring an extensible list of sensitive substring matches and fixed-length masking to prevent leakage of actual credential lengths or prefixes.
**Prevention:** Always enforce strict folder permissions (0o700) on parent credential folders (such as `~/.agent-reach` and `~/.config/xfetch`) and file permissions (0o600) via explicit `os.chmod` on Unix platforms. Centralize and reuse secure syncing functions to prevent duplicate implementations, and use comprehensive case-insensitive substring matching combined with fixed-length masks (`****`) for short sensitive keys.
