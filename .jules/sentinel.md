## 2025-05-22 - Enforcing Secure Permissions on Existing Files
**Vulnerability:** Use of `os.open` with `O_CREAT` and a mode bitmask (e.g., `0o600`) does not modify the permissions of an existing file if it already exists; it only applies to newly created files. This creates a risk where a configuration file manually created with broad permissions (e.g., `0o644`) would remain world-readable even after the application "saves" it with restricted flags.
**Learning:** To ensure restrictive permissions are always applied, an explicit `os.chmod` call is required after opening or writing the file, specifically on Unix-like systems. Additionally, the parent directory should also be restricted (`0o700`) to provide defense-in-depth against directory listing or unauthorized access attempts.
**Prevention:** Always follow file creation with an explicit `os.chmod(path, 0o600)` on non-Windows platforms when handling sensitive data. Verify these permissions in diagnostic health checks (`agent-reach doctor`).
