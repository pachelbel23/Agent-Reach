## 2026-03-16 - File Permission Enforcement Overwrites and Extensible Masking Identifiers
**Vulnerability:** Weak default file permissions on pre-existing configuration files (0o644 instead of 0o600) and credential data leakage via unmasked custom platform credentials (ct0, sessdata, csrf, cookie, jct).
**Learning:** Using `os.open` with `O_CREAT` and a mode bitmask only sets restrictive permissions when a file is newly created, but fails to modify permissions of an existing file. Therefore, an explicit `os.chmod` is always required to guarantee restricted owner-only permissions on subsequent overwrites. Additionally, standard security keyword filters (like 'key', 'token', 'password', 'proxy') fail to identify custom or platform-specific session identifiers (e.g., 'ct0', 'sessdata', 'csrf', 'cookie', 'jct'), leading to credential exposure in dictionary outputs.
**Prevention:** 1) Always enforce file permissions explicitly via `os.chmod` on Unix platforms regardless of whether the file was newly created or already existed. 2) Maintain an extensible list of platform-specific credentials and cookie keys within standard masking engines to avoid data leakage.
