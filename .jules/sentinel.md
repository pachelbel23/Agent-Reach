## 2026-03-16 - [Secure Config Permissions and Sensitive Cookie Masking]
**Vulnerability:** The configuration directory (`~/.agent-reach`) had default permissive umask permissions (e.g. `0o755`), making secrets browseable by other users on a multi-user system. Additionally, sensitive cookie fields like `ct0`, `sessdata`, `csrf`, `cookie`, and `jct` were not masked in `to_dict()`, and secrets shorter than 8 characters were leaked directly inside masked dictionary outputs. Finally, `_sync_xfetch_session` did not enforce restrictive permissions on directory creation or mitigate race conditions via secure `os.open` file creation.
**Learning:** System calls like `os.open` with `O_CREAT` only set permissions for *newly created* files; they do not restrict permissions of an existing file upon overwrite. To ensure security across overwrites, an explicit `os.chmod` is required on non-Windows systems. Furthermore, generic masking filters can easily omit platform-specific cookie naming conventions, requiring detailed domain-specific key lists and safe short-secret handling (like fixed-length masking).
**Prevention:** Always restrict home configuration directories to `0o700` and config files to `0o600` on Unix systems. Enforce these permissions both during directory creation (`mkdir`) and file write/overwrite (`chmod`). Use comprehensive lists of sensitive substring matches and fixed-length masking strings (`****`) for short secrets to avoid leaking prefix or length info.
