## 2026-07-30 - Existing File Overwrites and Short Secret Masking
**Vulnerability:** 1. Overwriting an existing configuration file using `os.open` with mode `0o600` fails to restrict permissions if the file already exists with broader permissions. 2. Masking sensitive values in `Config.to_dict()` by slicing the first 8 characters and adding an ellipsis leaks the entire value if the secret is less than 8 characters.
**Learning:** 1. On Unix-like systems, `os.open` with `O_CREAT` and mode flags only sets permissions when the file is created from scratch. It does not modify permissions of an existing file. Explicitly calling `os.chmod` is required to ensure restrictive permissions on updates. 2. A generic slicing mask fails to handle short credentials safely, leading to partial or full data leakage.
**Prevention:** 1. Always follow file creation/overwrite with an explicit `os.chmod` call on non-Windows platforms. 2. Implement conditional masking that replaces truthy short credentials (<8 characters) with a fixed-length string (e.g., `****`) and only uses slicing + ellipsis for longer secrets.
