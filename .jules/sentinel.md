## 2026-07-27 - Hardened Config Permissions, Masking and Credential Sync Security
**Vulnerability:** Weak default file/directory permissions on configuration files and credentials sync files could leak sensitive auth tokens (e.g., Twitter authToken, ct0). Furthermore, using `os.open` with `O_CREAT` only sets restrictive permissions (0o600) upon file creation, leaving existing files with wider access untouched on subsequent saves.
**Learning:** `os.open` with `O_CREAT` does not modify file permissions for existing files. A race condition is also present when credentials files are created with standard `open()` and subsequently secured via `os.chmod()`, as they remain briefly readable to other users/processes.
**Prevention:** Always enforce restrictive directory permissions (0o700) on parent folders, use an explicit `os.chmod` to restrict permissions to 0o600 even if the file already exists, and avoid race conditions by creating credentials files with secure flags (`os.O_CREAT | os.O_WRONLY | os.O_TRUNC`) with mode `stat.S_IRUSR | stat.S_IWUSR` from the outset.
