## 2026-03-22 - [Extensible Sensitive Naming and Length Masking for Configuration Dictionaries]
**Vulnerability:** Platform-specific credentials/cookies containing sensitive tokens like `ct0`, `sessdata`, `csrf`, `cookie`, and `jct` were exposed in plaintext in `Config.to_dict()` output. Additionally, short secrets (< 8 characters) were partially leaked (revealing length and first letters) through prefix truncation (`f"{str(v)[:8]}..."`).
**Learning:** Generic security masking keywords like "key", "token", "password" fail to capture platform-specific session identifier patterns. Masking logic that truncates secrets based on a minimum length should fall back to a safe fixed-length mask (e.g., `****`) for shorter values to prevent leaking exact length or character prefix info.
**Prevention:** Maintain an explicit, case-insensitive list of platform-specific secret keys (such as `ct0`, `sessdata`, `csrf`, `cookie`, `jct`) in the masking logic, and ensure all non-empty secrets are masked securely with a fixed-length mask if they are shorter than the prefix truncation threshold.
