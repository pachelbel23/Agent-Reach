## 2026-04-13 - [Sensitive Config Data Masking and Permission Hardening]
**Vulnerability:** Incomplete masking of platform-specific session identifiers (e.g., 'ct0', 'sessdata', 'csrf', 'cookie', 'auth', 'jct') in configuration dictionaries results in a data leakage vulnerability when configuration dictionaries are logged or printed. Additionally, config directory creation and existing file permission overwriting did not guarantee secure permissions.
**Learning:** `to_dict` must comprehensively mask all session and secret identifiers, and generic security masking keywords like 'key' or 'token' fail to capture variety in platform-specific session naming conventions. Furthermore, `os.open` with `O_CREAT` does not modify permissions of an existing file; an explicit `os.chmod` is required to ensure restrictive permissions on overwrites.
**Prevention:** Maintain an extensible identifier list for sanitization logic and explicitly call `os.chmod` on both directory and files when saving configurations on non-Windows platforms.
